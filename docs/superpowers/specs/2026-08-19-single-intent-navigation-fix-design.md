# 单次意图换幕与第五幕即时反馈修复设计

## 问题与根因

- 正文横滑后，iPhone Safari 可能继续保留正文按钮焦点，使导演状态残留 `reading` 暂停。当前换幕请求只主动解除 `gesture` 和 `surface-focus`，因此第一次点击或上划可能只解除焦点，第二次才进入退出阶段。
- 第五幕四个频道选项在入场画面中已经可见，但导演进入 `present` 前约 680ms 仍为禁用状态。浏览器会直接丢弃这段时间内的点击，所以用户看不到选择或反馈。

## 修复行为

- 导演处于 `ready` 且页面可见时，一次明确的按钮点击、字幕外上划或键盘换幕命令立即进入 `exit`。
- `reading`、`gesture`、`surface-focus`、`control-focus` 和 `control-interaction` 等临时暂停不再阻止显式换幕；`hidden` 仍然阻止后台页面换幕。
- 第五幕频道按钮从场景出现起即可选择，不再存在“可见但不可点”的入场窗口。
- 第一次频道选择在同一轮状态更新中锁定频道、揭示该频道第一段正文，并展示对应的“认真追问”反馈。
- 如果用户在入场动画结束前极快读到末段，导演也能从 `enter` 正确进入 `ready`，不会丢失完成通知。
- 现有入场、退出动画时长、正文左右滑动规则、频道分支内容和终幕行为保持不变。

## 组件边界

- `lib/director.ts`：把显式换幕的阻塞条件收敛为仅 `hidden`；允许 `PRESENTATION_COMPLETE` 从 `enter` 或 `present` 进入 `ready`。
- `components/experience/EchoExperience.tsx`：第五幕在 `enter` 和 `present` 阶段均可互动；退出和隐藏时仍不可互动。
- `components/experience/scenes.tsx`：频道选择继续保持幂等，一次点击只锁定一个频道并揭示一次首段。
- 测试通过真实焦点残留、一次点击、一次上划、第五幕入场期首击和快速读完路径复现并锁定行为。

## 验收标准

- 正文停留焦点时，首次点击换幕按钮即让按钮消失并进入退出阶段。
- 正文停留焦点时，首次字幕外上划即进入退出阶段。
- 页面处于后台时，显式换幕仍被拒绝。
- 第五幕刚出现但 `enterMs` 尚未结束时，首次点击任一频道立即显示频道名称、首段正文和对应反馈。
- 快速读完第五幕仍可正常出现换幕入口。
- 完整测试、lint、Pages 构建、390×844 移动端实测和线上部署验证通过。
