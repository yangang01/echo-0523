# 全场景手动阅读设计

## 目标

将八个场景统一改为用户主动推进的阅读体验：每段回音由用户点击“读取下一段”揭示，最后一段揭示后再由用户点击“进入下一幕”。不再因为固定 10 秒计时而切换文字或场景。

## 交互规则

- 场景进入后只展示标题、正文和必要的场景前置互动。
- 前置互动完成后，显示“读取下一段”按钮；按钮每次只揭示一个尚未解锁的回音。
- 最后一段揭示后，显示“进入下一幕”按钮；点击后进入现有 exit 编排。
- 上划和键盘导航仍可作为快捷推进方式，但只在当前场景已经满足前置条件时生效。
- 已解锁回音继续支持圆点回看；回看不改变手动推进顺序。
- 页面隐藏、暂停或场景非 active 时，手动推进按钮禁用且不会产生回调。

## 架构

`scenes.tsx` 增加无计时的 `useManualScene`，以 cues 顺序、前置条件和暂停状态管理下一段；场景组件在自己的 action 区渲染统一的手动按钮。`useAutomaticScene` 不再被任何场景使用，`presentMs` 只保留为历史时间线兼容字段，不参与揭示或完成。`EchoExperience` 继续只负责最后一步的场景切换。

## 验证

- 场景单测覆盖每个场景逐段点击、重复点击、暂停/失活和完成回调只触发一次。
- 集成测试覆盖首幕和完整旅程：无计时自动揭示，最后一段后仍停留，点击“进入下一幕”才切换。
- 全量 Vitest、ESLint、Pages 构建和线上移动端验收必须通过。
