# A Moment Apart 背景音乐集成设计

## 目标

将项目根目录中的 `Odesza - A Moment Apart.mp3` 集成为七夕 H5 的主背景音乐。音乐应在首次有效用户互动后自动播放，与现有 Y/U 粒子叙事同步存在，并能直接随 GitHub Pages 公共仓库发布。

## 音频资源

- 源文件：项目根目录 `Odesza - A Moment Apart.mp3`，约 9 MB。
- 发布路径：`public/audio/a-moment-apart.mp3`。
- GitHub Pages 构建必须将音频复制到带仓库 base path 的公开产物中，并由产物验证器检查文件存在。
- 页面引用必须使用构建 base URL，不能依赖站点部署在域名根路径。

## 播放体验

- 初始状态保持静音，避免浏览器自动播放限制。
- 第一次有效用户互动后自动启动音乐：开场 Y 拖拽/键盘启动，以及页面内其他明确点击、触摸或键盘操作都可作为解锁动作。声场按钮不走自动启动捕获，而是只执行其明确的开关语义，避免一次点击先开后关。
- 播放成功后，顶部声场状态显示 `ON`。
- 音乐在约 2.5 秒内淡入，正常目标音量为 `0.16`。
- 背景音乐循环播放；循环边界采用短淡化，避免明显断点。
- 最终幕可将目标音量平滑提升至 `0.20`，离开或重播后恢复 `0.16`。
- 页面进入后台时暂停；回到前台后从原播放进度继续，不重新开始。
- 用户点击声场按钮时同时控制背景音乐与现有场景提示音。
- 浏览器拒绝首次播放时，体验继续运行、控制状态保持 OFF，用户随后点击声场按钮可重试。

## 场景提示音

- 保留现有 Web Audio 心跳、锁定、回音与绽放提示。
- 提示音的合成配方不变，但最终增益缩放为当前值的约 `35%`。
- 提示音与背景音乐共享启用/暂停状态，页面隐藏时一并暂停。
- 背景音乐播放失败不影响提示音引擎的安全清理。

## 架构

- `AudioEngine` 继续负责 Web Audio 场景提示音，并新增一个稳定的原生 `HTMLAudioElement` 管理背景音乐。
- `AudioEngine` 暴露一个窄的命令接口；根交互捕获器必须在原始 `pointerdown` 或 `keydown` 调用栈内直接执行 `audio.play()`，不能等 React effect 再播放，否则移动端可能判定已离开用户手势。
- 音频元素在组件生命周期内只创建一次；切幕不重建，不丢失播放位置。
- 淡入、淡出和最终幕音量变化通过单一可取消的动画调度器驱动，避免并发定时器争抢音量。
- `EchoExperience` 维护声场意图，并在首次有效交互时请求开启；只有 `play()` 成功后才确认 ON。
- 自动启动、按钮切换、隐藏页暂停和恢复必须幂等，React Strict Mode 下不得重复创建音频或重复播放。

## 失败与降级

- `HTMLAudioElement.play()` 拒绝时捕获 Promise rejection，不产生未处理异常。
- 加载失败时保留完整无声体验，声场按钮仍可重试。
- 不支持 Web Audio 时只播放背景音乐；不支持背景音乐播放时仍允许现有提示音安全降级。
- 卸载时取消音量动画、暂停音乐、移除事件监听器并关闭 AudioContext。

## 测试与验收

- TDD 覆盖：首次互动自动启动、播放成功后 ON、拒绝后保持 OFF、按钮重试、淡入目标音量、最终幕提升、循环边界、隐藏暂停/恢复、卸载清理。
- 验证提示音增益缩放至原来的约 35%，并保留 cue 切换行为。
- 验证音频元素在八幕切换中保持同一实例和播放位置。
- GitHub Pages 构建产物必须包含 `audio/a-moment-apart.mp3`，HTML/JS 引用使用仓库 base path。
- 完整 Vitest、ESLint、Pages 构建与产物校验、vinext 生产构建、`git diff --check` 均须通过。
- 最后在移动端尺寸验证首次触碰播放、声场按钮、后台恢复和最终幕音量变化。

- 验证提交中没有遗漏大文件，且单个文件低于 GitHub 100 MB 限制。
- 合并并推送 `main` 后观察 GitHub Pages workflow，确认 HTML、JS、CSS、图片与 MP3 均返回 HTTPS 200。
