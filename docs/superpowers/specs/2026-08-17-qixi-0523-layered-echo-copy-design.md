# 0523 回音星核：分层回音内容扩写设计

日期：2026-08-17

## 目标

把现有约两分钟、主叙事约 170 字的体验扩展为 7–9 分钟。新增内容必须来自两人已经真实发生的相处：吃醋、2026 年 5 月 23 日表白、她喜欢被偏爱、分享生活日常、认真追问与夸奖、陪她吐槽、午间游戏和深夜电话。

文案不写道歉信，不讨论“学会信任”，不许下无法保证的未来承诺。核心表达是：她的分享会被认真听见，她需要回应时会得到当下的回应。

## 文案语气

采用“电影旁白 + 本人聊天口吻”的混合方式：

- 旁白负责建立宇宙、信号、坐标和回音的画面感。
- 关键句切换成对“小宝贝”的直接表达，口吻自然、具体，允许一点吃醋和可爱。
- 避免华丽词汇连续堆叠；每个抽象表达后必须跟随一个真实相处细节。
- 每个回音片段为 30–55 个汉字，每幕 3–4 个片段；用户单次完整体验读到的主文案目标为 900–1200 个汉字。四个日常频道的分支文案分别计入内容库，不要求全部在单次体验中出现。

## 八幕叙事

### 01 唤醒：只为她开放的入口

1. 电影旁白：一个沉睡的宇宙在她触碰后苏醒。
2. 真实表达：这里存放的是平时聊天时没有完整说出口的话。
3. 直接对话：告诉小宝贝，她不是来旁观一场动画，而是这个宇宙唯一的接收者。

解锁方式：长按期间在 33%、66%、100% 三个节点解锁；三次触碰的移动端备用操作分别对应同样三个节点。

### 02 吃醋：心跳异常的真实来源

1. 看到别人夸她漂亮时，明知道她本来就会被喜欢，心里仍然会酸一下。
2. 她对别人笑时，会忍不住想把那份笑留给自己；承认这份有点幼稚的占有欲。
3. 不把情绪变成责怪，说明真正想表达的是“我太在意你，也太喜欢你看向我时的样子”。

解锁方式：心跳解码进度达到 35%、60%、85%；达到 92% 后允许完成本幕。

### 03 表白坐标：2026.05.23

1. 锁定 2026：这一年因为她出现而有了清晰坐标。
2. 锁定 05：五月原本只是普通月份，后来装下了一次认真说出口的喜欢。
3. 锁定 23：从这一天起，05:23 不只是时间，也成为两个人共同拥有的暗号。
4. 完成坐标：承认表白并非故事终点，而是日常开始有了名字。

解锁方式：三个日期按钮分别解锁一段；全部锁定后显示收束段。

### 04 偏爱权限：她日记里的那句话

1. 直接引用含义而不伪造原句：“你说过，特别喜欢被我偏爱的感觉。”
2. 告诉她这句话被认真记住，不是一句听过就算的话。
3. 写她在自己眼中可爱、漂亮的具体状态：认真分享、开心时笑、气鼓鼓地吐槽。
4. 把偏爱落在当下的行动：多问一句、多听一会儿、及时回音、站在她这一边。

解锁方式：三颗偏爱星分别解锁前三段；全部点亮显示行动段。

### 05 日常回音：她说的都不是小事

用户先选择“发生了小事、想吐槽、今天超开心、想被夸夸”之一。每个频道包含三层回应：

1. 认真追问：不只回复“嗯嗯”，而是追问人物、过程和她最在意的瞬间。
2. 偏爱夸奖：根据频道给出自然、具体的可爱或漂亮表达。
3. 站她这边：陪她吐槽、放大快乐，或者安静把小事听完。
4. 三种回应完成后补一段收束：内容有没有主题不重要，重要的是分享的人是她。

每个频道使用不同正文，避免四个入口只是换标题。

### 06 午间双人副本：短暂却专属的空隙

1. 靠近：上班间隙时间很碎，但听见她上线就会期待。
2. 同步：输赢和操作不是重点，一起笑、一起配合才让普通午间发亮。
3. 穿越：游戏结束后各自回到忙碌里，那段短时间仍然只属于两个人。
4. 完成副本：陪伴不总需要宏大的安排，有时就是忙碌中仍愿意为彼此留出一局。

解锁方式：三个关卡各解锁一段，通关后显示收束段。

### 07 深夜同频：没有主题也不想挂断

1. 33%：躺在床上聊白天的小事，声音比话题更重要。
2. 66%：偶尔没有新话题，短暂安静也不会尴尬。
3. 100%：明明该睡了，却会因为舍不得结束而再聊一句。
4. 完成连接：喜欢的不是某个精彩话题，而是电话另一端一直是她。

解锁方式：连接进度跨过三个阈值时解锁；完成后显示收束段。

### 08 无限回音：已经发生的陪伴

1. 回看她分享生活、打电话、午间游戏和睡前聊天形成的日常。
2. 说明“无时无刻的陪伴和回应”不是口号，而是这些已经发生的小片段。
3. 收束为当下表达：“你说的有的没的，在我这里都不是小事。因为是你说的，所以我想听完。”
4. 显示实时相伴计时、收件人“小宝贝”、署名“永远爱你的人”和起始日期 2026.05.23。

解锁方式：用户主动触碰三次读取前三段；第三次后无限环完全展开并显示签名与计时。终幕不自动滚动。

## 回音字幕组件

新增一个跨八幕复用的 `EchoTranscript` 组件，职责单一：接收当前幕片段、已解锁数量和当前片段索引，展示阅读状态并允许回看。

- 屏幕上始终只展示一个主要片段，防止遮挡粒子主体。
- 新片段以 400–600ms 淡入、微光扫描和轻微上浮出现。
- 已解锁片段缩成发光刻度，点击刻度可回看；回看不改变互动完成状态。
- 新片段解锁后自动切到最新内容，但文字不自动消失，也不自动翻到下一段。
- 当前片段使用 `aria-live="polite"`，减少动画模式下取消逐字与扫描，只保留即时显示。
- “继续航行”只有在互动完成且本幕最后片段已经解锁后出现。

## 状态与数据

`lib/content.ts` 保存结构化片段数据，不把长文案散落在组件 JSX 中。每幕提供稳定片段 ID、正文和解锁节点；四个日常频道分别提供独立片段。

场景组件继续负责原有互动状态，并在越过解锁节点时报告片段 ID。体验容器维护每幕已解锁片段和当前阅读索引。重新进入宇宙时同时清空阅读状态。

重复触发同一阈值不得重复插入片段。快速连续点击不得跳过片段或提前显示“继续航行”。

## 版式与节奏

- 手机竖屏优先。字幕位于主标题与互动控件之间，宽度不超过 430px。
- 每个片段控制在手机屏幕 3–5 行；过长内容拆成两个片段，而不是缩小字号。
- 小高度设备允许字幕区域内部滚动，但页面主体仍不滚动。
- 桌面端字幕与交互保持左对齐，并让粒子主体占据右侧主要空间。
- 目标平均每幕 45–70 秒，总体验 7–9 分钟；阅读速度完全由用户控制。

## 验收与测试

自动化测试覆盖：

1. 八幕均包含 3–4 个非空片段，任一频道路径的单次完整体验主文案为 900–1200 个汉字。
2. 文案包含已确认的真实细节和称呼，不包含“学会信任”或具体未来保证。
3. 各互动阈值只解锁一次，重启后清空进度。
4. 日常四个频道均包含认真追问、偏爱夸奖、站在她这边和收束段。
5. 最后一段未解锁时不能进入下一幕。
6. 回看旧片段不影响完成状态，最新片段解锁后成为当前片段。
7. 移动端 390×844 下字幕、互动和“继续航行”不相互遮挡。
8. 减少动画模式下所有正文可立即阅读。

最终进行一次完整手机端走查，逐幕确认解锁顺序、文本可读性、视觉遮挡和终幕展开。
